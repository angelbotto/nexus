<objective>
Add LRU webview pool management to Nexus so that recently-used webviews stay alive for instant switching while older ones are evicted to keep RAM under 500 MB.

Purpose: This is the core performance mechanism. Webviews are already lazy (created on first click), but there is no eviction — every visited app stays alive forever, consuming RAM. The LRU pool caps the number of alive webviews at 8 and silently destroys the oldest when exceeded.

Output: Modified state.rs with LRU tracking, modified switch_app_impl with eviction logic.
</objective>

  **LRU update + eviction block (after updating active_app_id):**

  Replace the existing "Update active app" block at the end of switch_app_impl with a combined block that:

  1. Locks state
  2. Sets `active_app_id = Some(app_id.clone())`
  3. Updates lru_order: `retain(|id| id != &app_id)` then `push_back(app_id.clone())`
  4. Collects evicted IDs: while `lru_order.len() > LRU_POOL_SIZE`, pop_front. Skip if it equals the active app (push it back and break). For each evicted ID, also remove from `webviews_created`.
  5. Drops the lock
  6. Closes evicted webviews OUTSIDE the lock: `app_handle.get_webview(&format!("app-{}", id))` then `wv.close()`

  **CRITICAL anti-deadlock pattern:** Collect evicted IDs into a `Vec<String>` while the mutex is locked. Drop the lock. THEN iterate and call `wv.close()` on each. Never call `wv.close()` while holding the Mutex.

  Also update `destroy_webview` command to remove the app from `lru_order`:
  Add `st.lru_order.retain(|id| id != &app_id);` after `st.webviews_created.remove(&app_id);`

  Import `LRU_POOL_SIZE` from state module: `use crate::state::{AppState, LRU_POOL_SIZE};` (update existing import).
