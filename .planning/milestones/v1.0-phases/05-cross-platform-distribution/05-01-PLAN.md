  <name>Task 1: Platform-conditional Cargo deps, release profile, config path, session isolation, and shortcut modifier</name>
  <files>src-tauri/Cargo.toml, src-tauri/src/config.rs, src-tauri/src/routing.rs, src-tauri/src/commands/webview.rs, src-tauri/src/lib.rs</files>
  <action>
**Cargo.toml changes:**
1. Move objc2, objc2-quartz-core, objc2-app-kit from `[dependencies]` to `[target.'cfg(target_os = "macos")'.dependencies]` with same versions and features.
2. Add `[profile.release]` block: `codegen-units = 1`, `lto = true`, `opt-level = "s"`, `panic = "abort"`, `strip = true`.

**config.rs changes:**
Replace `config_path()` with platform-aware version using `#[cfg]` blocks:
- macOS: `dirs::home_dir()` -> `.nexus/apps.json` (unchanged)
- Windows: `dirs::config_dir()` -> `Nexus/apps.json` (config_dir = %APPDATA%)
- Linux: `dirs::config_dir()` -> `nexus/apps.json` (config_dir = ~/.config)
Remove `use dirs::home_dir;` import at top, use `dirs::home_dir()` / `dirs::config_dir()` inline.

**routing.rs changes:**
Wrap `make_store_id()` in `#[cfg(target_os = "macos")]` since it produces the `[u8; 16]` for `data_store_identifier` which is macOS-only. Add a `platform_data_dir(app_id: &str) -> PathBuf` function for Windows/Linux:
- Windows: `dirs::data_local_dir().join("Nexus").join("webdata").join(app_id)`
- Linux: `dirs::config_dir().join("nexus").join("webdata").join(app_id)`
- macOS: `PathBuf::new()` (unused, data_store_identifier handles it)

Keep the existing `make_store_id` tests behind `#[cfg(target_os = "macos")]` in the test module.

**commands/webview.rs changes:**
In `switch_app_impl`, the webview creation block:
1. Wrap `let store_id = make_store_id(&app_id);` in `#[cfg(target_os = "macos")]`
2. Replace the single `.data_store_identifier(store_id)` call with cfg-guarded alternatives:
   ```rust
   #[cfg(target_os = "macos")]
   let builder = builder.data_store_identifier(store_id);
   #[cfg(not(target_os = "macos"))]
   let builder = builder.data_directory(crate::routing::platform_data_dir(&app_id));
   ```
   This requires extracting the WebviewBuilder into a `let mut builder = ...` variable first, then applying platform-specific methods, then passing to `main_window.add_child(builder, ...)`.
3. The `#[cfg(target_os = "macos")]` block on `child_wv.with_webview(...)` for corner radius is already correct — leave it as is.
4. Update imports: add `#[cfg(target_os = "macos")]` on the `use crate::routing::make_store_id;` (or use fully qualified path).

**lib.rs changes:**
1. Add a helper function at module level:
   ```rust
   #[cfg(target_os = "macos")]
   fn cmd_modifier() -> Modifiers { Modifiers::SUPER }
   #[cfg(not(target_os = "macos"))]
   fn cmd_modifier() -> Modifiers { Modifiers::CONTROL }
   ```
2. Replace all `Modifiers::SUPER` comparisons in the shortcut handler with `cmd_modifier()`. There are comparisons for KeyN, KeyB, KeyK, KeyR, and the digit loop.
3. Replace all `Modifiers::SUPER` in `Shortcut::new(Some(Modifiers::SUPER), ...)` registration calls with `cmd_modifier()`.

**GAP_TOP adjustment for non-macOS:**
In commands/webview.rs, the `GAP_TOP` constant is 40.0 for macOS traffic lights. On Windows/Linux with native title bar, the webview should start at a smaller gap. Add:
```rust
#[cfg(target_os = "macos")]
const GAP_TOP: f64 = 40.0;
#[cfg(not(target_os = "macos"))]
const GAP_TOP: f64 = 12.0;
```
Similarly, `GAP` of 12.0 is for the macOS floating card aesthetic. On Windows/Linux with no corner radius, use 0.0 gap for edge-to-edge webview:
```rust
#[cfg(target_os = "macos")]
const GAP: f64 = 12.0;
#[cfg(not(target_os = "macos"))]
const GAP: f64 = 0.0;
```
